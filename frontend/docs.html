Wallet API v1

All amounts are integers in minor units (100 = 1.00). Authenticate every request from your server with Authorization: Bearer sk_test_…. Wallets are closed-loop: a balance can only be spent at the merchant that issued it, and there is no withdrawal endpoint.

Create or fetch a wallet

POST /v1/wallets
{ "customer_id": "cust_42", "display_name": "Ravi Kumar" }

→ { "customer_id": "cust_42", "balance": 0, "currency": "inr", "status": "active" }
GET /v1/wallets/{customer_id}

Top up

Creates a pending top-up and returns a checkout URL. Redirect your customer there. After paying they are sent to return_url?topup=top_…&status=succeeded. The wallet is credited only once the gateway confirms payment. Limits come from your wallet policy.

POST /v1/wallets/{customer_id}/topups
{ "amount": 100000, "return_url": "https://yourshop.com/wallet" }

→ 201 { "id": "top_…", "status": "pending", "checkout_url": "https://…" }
GET /v1/topups/{topup_id}
→ { "id": "top_…", "status": "succeeded", "amount": 100000 }

Charge (pay for an order)

Send an Idempotency-Key header so a retried request never charges twice. Returns 402 insufficient_funds if the balance is too low.

POST /v1/wallets/{customer_id}/charges
Idempotency-Key: order-1007
{ "amount": 24900, "reference": "order-1007", "description": "Weekly veg box" }

→ 201 { "id": "txn_…", "type": "charge", "amount": -24900, "balance": 75100 }

Refund

Refunds go back into the wallet, never to cash. Omit amount for a full refund.

POST /v1/refunds
{ "charge_id": "txn_…", "amount": 5000, "reason": "Missing tomatoes" }

Transactions

GET /v1/wallets/{customer_id}/transactions?limit=50

Errors

{ "error": { "code": "insufficient_funds", "message": "Wallet balance is too low", "balance": 1200 } }

Codes include invalid_api_key, merchant_not_approved, wallet_not_found, insufficient_funds, below_min_topup, above_max_topup, max_balance_exceeded, refund_exceeds_charge, idempotency_conflict.
